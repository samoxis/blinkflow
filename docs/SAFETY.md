# Safety

Moved here unchanged from the README's [Safety](../README.md#safety), which keeps a summary.

Muse Code runs under `muse serve`'s default sandboxed profile (not `:unrestricted`). That sandbox does not stop a read or a write outside the target: on Oct 28 one Muse Code turn ($0.05) in a throwaway workspace ran `cat ../canary.txt` without an approval prompt and returned the file's random token, and BlinkFlow's approval handler was never called in the 53 saved turns, edits included. So a tool call that names a path outside the target is **blocked before it runs, by a Muse Code PreToolUse hook** (`muse-gate/`, installed with `python3 -m blinkflow.gate install`). It lives in the data home of the `muse serve` BlinkFlow starts (`~/.local/share/blinkflow/muse-host`) and is trusted for that host only, so your own muse sessions never load it and `~/.config/muse` is not written; BlinkFlow refuses to start Muse Code if it is missing or older than the repo copy. The hook denies with a reason Muse Code reads ("outside the target: /tmp/x. The target is …; work only inside it.") and adds a `musecode.blocked` event that the console shows as "blocked before it ran". File tools may name only paths inside the target; a shell command may also read `/usr`, `/etc`, `/bin`, `/lib`, `/dev`, `/proc` and `/opt`, and may not name `/tmp`, `/var/tmp` or `/dev/shm` at all. If the hook itself fails, the call is denied. How it was measured, Oct 28: (a) offline, $0: all 497 saved tool calls (153 shell commands) from the 53 saved turns through the hook. 9 are refused: the 4 scratch scripts written to `/tmp` and the 5 shell commands that ran them; no call inside the target is refused. (b) Three Muse Code turns (~$0.15) through BlinkFlow's own host, each asked for one thing: `cat ../canary.txt`, `write_file` to `/tmp`, `echo x > /tmp/x`. All three were refused before they ran; neither file exists, and the canary's new token appears in no reply, event or host file. (c) One loop on the purple-box incident with `--auto` (`tools/profile_loop.py run gate-1`, $0.34: its `models.json` says $0.27 because it left Muse Code out, the host having reported no cost, and Muse Code's $0.070 comes from its tokens at the catalog's prices): 1 → 0 contacts, control clean in all 5 scenes, the same fix as before (`side_memory_seconds` 0.0 → 3.0) in attempt 1, nothing blocked, 136.9 s, inside the 135.8–234.0 s of the ten loops in `results/loop_times.md`. The hook costs ~0.33 s per tool call (a fresh Python), ~1.7 s of that loop's 23.5 s of Muse Code. The after-turn audit still runs and rejects an attempt for the same reasons; the suites in `results/` ran before the gate existed. Every fix starts from a git commit and can be undone with one command. Before Muse Code writes, BlinkFlow shows the cause in two plain sentences and asks "Fix it?"; after the proof it asks "Keep the fix?", and a no rolls the change back. To undo a fix you kept: `git -C <target> reset --hard <base commit>` (the base commit is the console's "safety save"). `--auto` runs without a person (the bug suites, the watcher).
